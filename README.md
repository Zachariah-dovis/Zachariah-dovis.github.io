# Zachariah Zhang — Personal Website

Source for <https://zachariah-dovis.github.io> — a personal site and the
*Randomness and Computation* notes blog, built as plain static files for
GitHub Pages.

## Design

A scholarly, high-dimensional-geometry visual system:

- **Paper & ink palette** — warm paper (`#F6F1E6`), deep indigo, copper and gold.
- **Three typefaces** — *Newsreader* for display headings, *Source Serif 4* for
  prose, *Inter* for UI. All self-declared via Google Fonts.
- **A polytope motif** — an inline SVG line drawing of a projected
  high-dimensional polytope, slowly rotating behind the hero and page headings.
- **Colour-coded statements** — definition / theorem / proof / remark paragraphs
  are detected at runtime and boxed with a coloured rail.
- **Reading furniture** — reading-progress ribbon, sticky table of contents with
  scroll-spy, and per-section anchor links on article pages.

No framework, no build step required to view the site. Everything is hand-written
HTML, one stylesheet, and one small script.

## Structure

```text
index.html          About / landing page
blog.html           Writing index: topic filters + search
posts/              Article pages
partials/           mathjax.html — shared MathJax config, inlined at build time
assets/             Images referenced by articles
styles.css          The entire design system (single stylesheet)
script.js           Progressive enhancement: progress, TOC spy, filters, boxes
build.mjs           Regenerates the page shells from the article bodies
.nojekyll           Tells GitHub Pages to serve files verbatim
```

## Editing content

Article **bodies** in `posts/*.html` are the source of truth. Everything around
them (page shell, masthead, sidebar, table of contents, pagination, reading time,
meta tags, structured data) is generated by `build.mjs`.

```bash
node build.mjs
```

The build is **idempotent** — it reads each `posts/*.html`, extracts the
`<div class="article-content">` body, and re-injects it into a fresh page shell.
Running it repeatedly produces byte-identical output, so it is always safe to
re-run.

To add a post:

1. Drop the new article into `posts/<slug>.html`.
2. Add an entry to the `AUTHORED` array at the top of `build.mjs` (title, tag,
   blurb). Array order drives the blog index order *and* the prev/next pager.
3. Run `node build.mjs`.

Editing an article's prose directly in `posts/*.html` is fine — re-running the
build preserves it. Widely used content components (`.model-box`,
`.frontier-box`, `.algorithm-map`, `.dictionary-table`, `.formula-strip`,
`.compact-list`, `.phase-list`, `.references-list`) are styled in `styles.css`
for backwards compatibility with existing notes.

## Math

MathJax 3 renders LaTeX from either delimiter style:

- `$…$`, `$$…$$`, `\(…\)`, `\[…\]`
- pre-rendered `<span class="math inline">` / `<span class="math display">`
  wrappers, which is how the notes exported from Notion are marked up

The config lives in `partials/mathjax.html` and defines the macros `\N`, `\R`,
`\Z`, `\Q`, `\C`, `\E`, `\P`, `\thicksim`, and `\mathscr`.

## Accessibility & performance

- Per-page `lang`, viewport, description, canonical, Open Graph and JSON-LD.
- Skip-to-content link, visible focus rings, `aria-current` navigation state.
- Search results announced through an `aria-live` region; topic filters expose
  `aria-pressed`.
- Full `prefers-reduced-motion` support and a dedicated print stylesheet.
- Zero dependencies — no tracking, no analytics, no runtime framework.

## Deploy

Push to `main`. GitHub Pages serves the repository root directly
(**Settings → Pages → Deploy from a branch → `main` / `/root`**).

```bash
git add -A && git commit -m "Redesign" && git push
```
